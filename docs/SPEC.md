# SPEC.md — 01 Arrangement Support 仕様

## 1. 目的

スティールダーツ 01（Double Out）のアレンジについて、
**答えを表示するのではなく「判断規則」を身につけられる**ことを目的とする。

ユーザーが理解できるようにすること:

- なぜそのナンバーを狙うのか
- なぜ別ルートより安全なのか
- シングルへ外した場合どうなるのか
- 隣接ナンバーへ外した場合どうなるのか
- 次ラウンドへ何点を残すべきなのか

## 2. 設計上の制約

- **生成 AI を runtime の判断に使わない。** 判断は決定論的・再現可能・テスト可能・
  オフライン動作可能な rule based engine で行う。
- ログインなし / バックエンドなし / 外部 DB なし / OpenAI API なし / Claude API なし。
- アプリ本体は完全にオフラインで動作する。
- 秘密情報を必要としない構成（公開リポジトリ前提）。

## 3. ルール

- スティールダーツ、**Double Out**。
- 合法セグメント: `S1〜S20` / `D1〜D20` / `T1〜T20` / `S-BULL = 25` / `BULL = 50` / `MISS = 0`。
- 最終ダートは **Double または BULL**。**BULL = 50 は Double 25 として合法な finish** とし、
  人工的に禁止しない。ただし基準ルートは Excel のデータを尊重する。
- アウターブル（25）では上がれない。

### Bust

次をすべて Bust として扱い、ビジット開始時の残りへ戻す。

- 残りが 0 未満になる
- 残りが 1 になる
- 残りが 0 になったが、最終ダートが Double / BULL ではない

## 3-1. 残り点（LEFT）の入力

実戦中の操作を減らすため、確定操作を挟まない。

- CHECKOUT / SETUP を開いた直後は **空欄（未入力）** から始まる。
  入力するまで候補を計算・表示せず、既定値のルートは出さない。
- **確定ボタン（「セット」）は置かない。** 有効な整数（CHECKOUT は 2〜170、
  SETUP は 171〜350）になった時点で、そのまま候補を再計算する。
- 空欄はエラーにしない。空欄へ戻したら候補を消して未入力状態へ戻る。
- 範囲外では候補を計算しない。入力途中の一時的な無効値ではエラーを出さず、
  入力欄を離れた（blur した）時点でだけ範囲を示す。
- 入力欄に focus すると現在値を全選択し、次の数字でそのまま置き換えられる。
- CHECKOUT と SETUP は別々の状態を持つ。モードを切り替えたら残り点を持ち越さず、
  空欄から始める。
- **よく使う値のプリセットボタンは置かない**（v1.2 で廃止）。
  実戦で必要なのは任意の残り点なので、10 個のボタンが縦を占有するだけになっていた。
  未入力時は `例 103` / `例 302` の placeholder で入力例を示す。
- **入力途中では画面を動かさない。** 103 を打つ途中の `10` もそれ自体は合法な
  CHECKOUT 値なので、有効値になっただけで自動スクロールしてはいけない。
  画面移動は **Enter / Done、または値を書き換えたあとの blur** でだけ行い、
  移動先は StatusBar ではなく答えである STANDARD / BEST の先頭にする。
  iOS では keyboard が閉じてビューポートが確定するのを待ってから動かす。
  3 桁入力になっただけで自動 blur することはしない。

## 4. モード

トップ画面に **CHECKOUT / SETUP / TRAINING** の 3 モードを置く（加えて「設定」）。

### 4-1. CHECKOUT（残り 2〜170）

- **STANDARD**: 基準ルート（`docs/CHECKOUT_DATA_POLICY.md`）
- **MY ROUTE**: ユーザーの得意ダブル（複数選択・並び順が優先度、BULL 可）を反映した並び。
  STANDARD の並びは変えない。得意ダブルの既定は**未設定**で、
  1 つも選んでいないあいだ MY ROUTE は表示しない（v1.3.5）。
- **WHY THIS ROUTE?**: 理由コードから組み立てた説明（`docs/ARRANGE_RULES.md`）
- **OTHER ROUTES**: 初期表示は上位 5 件。「すべて表示」を押すと、STANDARD / MY ROUTE として
  別枠に出したものを除いた**合法な候補をすべて**出す（件数の表示と実際の表示件数は必ず一致させる）。
  CHECKOUT では合法な候補が 1400 件を超えることがあるため、
  一度に描画すると重い場合に備えて「さらに 40 件表示」の段階表示も併せて置く。
  段階表示を使っても「すべて表示」で全件へ到達できることを必須とする。

登録済みルートだけを表示するのではなく、残り点と残り本数から
**数学的に成立する Double Out ルートを探索**する。

#### 4-1-1. 盤面の狙い方（2026-09-24）

42 / 46 / 48 / 39 / 43 の 5 点だけ、STANDARD の直下に読み取り専用の
「盤面の狙い方」カードを置く。既存の基準ルートは 1 本ずつ別のルートとして並ぶが、
このカードは**盤面で隣り合うシングルを一まとまりの的として見る**考え方を補う。

| 残り | エリアのナンバー（盤面の順） | Bust する的 |
| ---: | --- | --- |
| 42 | 6・10 | なし |
| 46 | 6・10 | なし |
| 48 | 16・8 | T16（0 点ちょうどだが最後がトリプル） |
| 39 | 17・3・19・7 | T17・T19（超過）、D19（1 残り） |
| 43 | 3・19・7 | T19（超過） |

- **エリア内のナンバーに主従・優先順位を付けない。** 各ナンバーについて、
  着弾したときの事実（残り点・上がりのダブル・Bust）だけを同じ形で並べる。
  例えば 39 の 17 は「S17 → 22 → D11」「T17 は BUST」を事実として示すだけで、
  「基本」「条件付き」のような区分はしない。どこを主に狙うかを決めるには、
  残るダブルの評価や狙う範囲を含めた戦術判断と、`docs/APPROVALS.md` への記録が要る。
- 定義（`src/data/aimAreas.ts`）はナンバーの並びだけを持つ。各着弾の残り点・
  上がりのダブル・Bust は保存せず、表示のたびに `applyDart` / `isCheckoutable` /
  `isBogey` から導く（`src/engine/aimArea/aimArea.ts`）。
- 着弾ごとの分類: `bust` / `finish-next-dart`（次の 1 本でダブル・BULL） /
  `finish-in-two`（あと 2 本） / `next-visit`（今回は不可、次ラウンドなら可） /
  `bogey` / `above-range`。「次の 1 本」と「あと 2 本」は区別する
  （42 の外側 S15 → 27 は 3 本開始でも「次の 1 本」ではない）。
- エリアのすぐ外のシングル（42 なら S13 / S15）も並べ、2 つ以上のナンバーを
  一まとまりに見ても全方向のズレに安全ではないことを示す。
- **残り 1 本**ではエリアへの 1 投で上がれることはないので、狙いとしては出さず、
  その事実と Bust の注意だけを NEXT VISIT の直後に出す。
- 得意ダブル（設定）は、上がりのダブルに「得意」と注記するだけ。並びは変えない。
- 次のものには**関与しない**: 基準ルート、`rankCheckoutRoutes` の重み・並び・採点、
  MY ROUTE、SETUP、NEXT VISIT、TRAINING の出題・採点・履歴、SIMULATION。
- エリアは**シングル帯（内側・外側）**の話で、トリプル・ダブル帯まで安全とは書かない。
  ワイヤー上の一点を「最適」とも書かない。命中確率・勝率・「プロが使う」は主張しない
  （個人の散布データを持っていないため）。
- 対象を 5 点以外へ広げるときは、人間がレビューして別の変更として増やす。
  「隣り合う 2 つのシングルのどちらでも次の 1 本でダブル」という条件だけなら
  2〜170 で多数の点が該当するが、直接 1 本で上がれる点・BULL 必須の点・
  トリプル帯が危険な点が混ざるため、自動では公開しない。

### 4-2. SETUP（残り 171〜350）

次ラウンドに良い 3 ダートチェックアウトを残す組み立てを提案する。
考え方は `docs/SETUP_THEORY.md`。

- Bogey Number を避ける
- 「とりあえず TON」の罠を警告する
- S-BULL を正式な調整手段として扱う
- テンパイを作れない残りでは、その事実を伝える
- **第一ターゲットのトリプル狙いが同ナンバーのシングルへ落ちても、
  残り本数でテンパイを作れる入り方を優先する**（v1.3.4 / `SETUP_THEORY.md` §10）

CHECKOUT 中に上がれなくなったときの NEXT VISIT では、得意ダブルが残しの質より
優先されるのは **第 1 希望だけ**（v1.3.5 / `ARRANGE_RULES.md` §8）。

### 4-3. RECOVERY（CHECKOUT / SETUP の両方に内蔵）

1 投ごとに実際の着弾を SVG ダーツボードから入力できる。
入力するたびに残り点・残り本数を更新し、候補を再計算する。MISS も入力できる。
Bust したときは、ビジット開始時の残りへ戻ることが分かる UI にする。

### 4-4. TRAINING

- CHECKOUT TRAINING / SETUP TRAINING / RECOVERY TRAINING / MIXED TRAINING
- 回答は SVG ダーツボードのタップ。タップは「そこへ刺さった」ではなく**「そこを狙う」**の意味。
- **自動確定しない。**「回答する」ボタンで確定する。Undo あり。
- 採点は S / A / B / C。数学的に成立するルートを単純に不正解にしない。
  C は「正解ではあるが非推奨」とし、**非推奨理由を必ず表示する**。
- 同じ 3 セグメントでも**順番が違えば別ルート**として判定する。

教育設計の全体は `docs/TRAINING_DESIGN.md`。ここでは要点だけを書く。

#### ruleValid と learningCorrect（v1.3）

採点を 2 つの概念に分ける。

- `ruleValid` — ルール上その回答が成立するか
- `learningCorrect` — 学習目的として正解か

CHECKOUT / RECOVERY は合法な Double Out が完成すれば両方 true（C ランクでも正解）。
SETUP は合法に投げ切れても、残りが Bogey / 170 超えなら
`ruleValid = true` / `learningCorrect = false` とする。

**主 UI の正答率は `learningCorrect` で数える。**
「合法に 3 投投げただけ」を正解にしない。

#### SETUP TRAINING の形式（v1.3.5）

主教材は **1 投調整**（80%）、補助が **1 投目の選択**（20%）。
10 問なら 8 / 2、30 問なら 24 / 6。

v1.3.3 までの **3 投フル形式（`setup-full`）は新規出題を停止**した。
「とりあえず T20 を 3 本」でも正解になる問題が多く、
「なぜ最初から 19 へ振るのか」を学べなかったため。
保存済み履歴を読むために、型・採点・feedback は残してある。

1 投調整では「開始残り」「ここまでに実際に入った 2 投」「現在の残り」「残り 1 投」を提示し、
最後の 1 投だけを答える。ここまでの 2 投は**ユーザーの回答ではなく実際の結果**なので、
読み取り専用で表示し、回答欄へ入れない。
出題は **`decisionRequired`（狙うナンバーを変えると結果が変わる場面）** に絞る。

**SETUP の回答は「どのナンバーを狙うか」**（1〜20）で、盤面 62 セグメントは使わない（v1.3.5）。
1 投調整の採点も、そのナンバーのシングル面・トリプル面の**両方**で見る。

- `ruleValid` … ナンバーを 1 つ選べている
- `learningCorrect` … シングル面に入ってもトリプル面に入っても、
  次のラウンドで上がれる残りになる

「T20 に入れば上がれる」だけでは正解にしない。
安全なナンバーが 1 つも無い残り（190 以上など）では、これまでどおり
「実際に作った残りが上がれるか」で採点する。

1 投目の選択では「残り点」と「このラウンドは 3 投ある」ことを提示し、
**1 投目だけ**を答える。この形式では回答後に 170 以下になる必要がないため、
1 投調整とは別の採点ロジックを使う。

- `ruleValid` … 盤面上の合法なターゲットを 1 つ選べている
- `learningCorrect` … 得点用の開始ターゲットであり、かつ同ナンバーのシングルへ
  落ちても残り本数でテンパイを作れる

推奨解答は通常 Practice と同じ `rankSetupRoutes` から取る（同じ質なら
シングル落ちにも耐えるナンバーを優先する）。
推奨以外でも、条件を満たす回答はすべて `learningCorrect` とし、推奨度で差を付ける。

#### 出題（v1.3）

単純な random pick ではなく、category / difficulty / mode / review / 直近履歴を考慮した
sampler で決める（`src/engine/training/sampling.ts`）。random retry loop は使わない。

- SETUP は教育カテゴリの quota を満たす（出題できるカテゴリへ決定論的に再配分する）
- CHECKOUT / RECOVERY は難易度 quota を満たす
- MIXED は mode bag（10 問で 4 / 3 / 3、30 問で 10 / 10 / 10）
- 同じ問題は直近 5 問、同じ状況は直近 3 問に出さない
- MIXED の同じ種別は最大 2 連続、HARD は 3 連続させない
- 無限モードは 10 問ずつ生成し、前の chunk の末尾 5 問を直近履歴として引き継ぐ
- 候補不足時の緩和は決定論的で、緩めた回数を report できる

#### feedback（v1.3）

どの問題でも、回答後に「何を答えればよかったか」が必ず分かること。

1 判定 → 2 あなたの回答 → 3 その結果 → 4 おすすめ → 5 その結果 → 6 違いの理由 →
7 他の成立回答（必要な場合のみ）。

**すべての不成立理由で推奨解答を返す**（EMPTY / TOO_MANY_DARTS / BUST /
NOT_DOUBLE_FINISH / TOTAL_MISMATCH / NOT_FINISHED / LEAVES_BOGEY /
LEAVE_ABOVE_CHECKOUT_RANGE / FIRST_DART_SINGLE_MISS_DEAD_END /
FIRST_DART_NOT_SCORING_TARGET）。

1 投目の選択では、「あなたの回答」「おすすめ」の両方について
**シングルへ落ちた場合の残りと、その後テンパイを作れるか**を並べて見せる。

#### 出題設定

スコア帯 / MIN・MAX 自由指定 / 完全ランダム / 無限練習 / 10 問 / 30 問 / 時間制限あり。
スマートフォンで煩雑にならないよう、詳細設定は折りたたむ。

#### RECOVERY TRAINING の成立条件

RECOVERY TRAINING は、基準ルートの 1 投目を狙って同じナンバーのシングルへ落ちたあと、
**残り 2 本で Checkout を完成させる**問題とする。上がれない状態を SETUP 問題として混在させない。

- 実投を Double Out の状態遷移へ適用した結果が `continue` である
- 更新後の残り点を 2 本以内で上がれる合法 route が 1 件以上ある
- route の最終 dart は Double または BULL で、途中に Bust がない
- 出題時に確認した正答を TRAINING grader が正解として受理する

この条件を満たす候補だけを乱数選択の前に構築する。RECOVERY 単独と MIXED 内の
RECOVERY は同じ候補 pool を使い、同じ seed と設定からは同じ出題列を生成する。
この成立性は v1.3 の再設計でも変更していない。

#### 学習履歴（端末内）

正答率 / 回答時間 / 平均回答時間 / スコア別成績 / スコア帯別成績 / 上がりダブル別成績 /
学習カテゴリ別成績 / route rank / 非推奨 route 選択回数 / 苦手スコア / 間違えた問題 /
要復習 / 連続正解 / 学習履歴。

間違えた問題・苦手問題を重点的に再出題できる。復習対象は残り点だけでなく
`problemKey` / カテゴリ / 学習タグでも表現する。

V1 の履歴は破棄せず移行する。ただし**構造が壊れている、または情報不足で
正しく再評価できない記録を「不正解」として正答率へ混ぜない**。
そうした記録は統計から除外し、件数だけ `migrationSkippedCount` として残す。

初期版はログイン・クラウド同期・JSON Export/Import なし。ただし将来足しやすい構造にしてある。

### 4-5. SIMULATION（v1.4.0 / v1.4.1）

01 を 1 ゲーム通して自力でプレイするモード。既存モードと違い、**正解を選ぶ形式ではない**。

- 開始点数は 301 / 501 / 701 / 任意（CUSTOM）。既定は 501。
- プレイヤー能力として First9 PPR・Average PPR（0〜167）、ブレ方向（縦 / 横 / 均等）、
  最大ブレ（小 / 中 / 大）を設定する。設定は `oas.simulation.v1` へ保存する
  （Beta 版では `01as-beta:oas.simulation.v1`。`docs/BETA.md`）。
- 1 投ごとに盤面で狙いをタップすると、能力に応じた着弾が**実寸ボードの XY 座標**として
  決まり、その位置に表示される。得点ベースの命中率テーブルは使わない。
- 3 投ごとに、ユーザー自身が合計を暗算して入力する。内部の得点と違えば
  「計算ミス」としてその場で指摘し、**必ず内部の正しい得点で進める**。
- Double Out / BUST は既存の `applyDart` をそのまま使う。
- 誤タップ用に、直前の 1 投だけ UNDO できる（暗算入力の確定が境界）。
- **ゲーム中は推奨ルート・MY ROUTE・OTHER ROUTE・ヒントを一切表示しない。**
- 上がったあとに「ゲームの振り返り」（GAME REVIEW）を表示する。評価対象は **INTENDED TARGET（狙い）だけ**で、
  着弾のミスは判断ミスに数えない。
- 各設定には、意味と「何を基準に選ぶか」の説明を折りたたみで添える（v1.4.1）。
- ビジット最後の 1 投で次のラウンドへ残す場面は、**次のラウンドに 3 本使って
  Checkout できる数字を作れるか**を評価軸にする（v1.4.1）。
  特定の残り点（160 / 170 など）は特別扱いしない。
  悪い選択は「成立する」と「良い選択」を区別して明確に指摘する。
- SETUP 中でまだ 2 本以上残っている場面は、**同ナンバーのシングルへ落ちても
  テンパイを作る道が残るか**を、ビジット最後の 1 投は**次のビジットでダブルへ
  到達するまでに何を要求される残りか**を振り返りに反映する（v1.4.3）。
- 振り返りは、アプリのおすすめルートの 1 投目そのものを「もっと良い狙いあり」などと
  否定的に判定しない。「もっと良い狙いあり」は別の 1 投目を示せるときだけ使う（v1.4.4）。
- CHECKOUT で、狙いから始まる上がり方がおすすめと戦術評価（基準ルート加点を除く）で同等以上で、
  おすすめに無い弱点を持たないなら、推奨度 B / C でも否定的に判定しない（v1.4.5）。
  上がれるルートがあるだけでは「良い判断」にしない。
- NEXT VISIT で、狙いが第 1 案以外の提案の 1 投目なら、第 1 案が明確な上位互換
  （残しの Tier・残しの質・難易度・シングル落ち後・的の切り替え・得意ダブルのすべてで同じか上）
  でない限り否定的に判定しない（v1.4.6）。提案だから「良い判断」、にはしない。
- ビジット最後の 1 投で、狙いが表示された NEXT VISIT の提案の 1 投目なら、代案との差が
  「狙い通りのときに残る外側のダブル」と「シングル落ち後の立て直し」の交換条件だけのときは
  否定的に判定しない。得意ダブルが代案側のダブルを優先していれば従来どおり（v1.4.7）。
- 改善候補には「振り返りが比べた代案」と「この場面のアプリの第 1 案」を分けて添える。
  第 1 案が減点した狙いと同じ 1 投目なら、改善案ではないことを明記する（v1.4.8）。

着弾モデル・キャリブレーション・レビューの判定は `docs/SIMULATION_DESIGN.md`。

### 2026-09-26 の限定整合修正

- CHECKOUT / SETUP は LEFT と残りダーツ1・2・3本を直接指定できる。初期値は3本。途中参照では過去の投球を作らず、Undo は参照開始点まで。開始点不明で BUST した場合は本当のラウンド開始点を再入力してから次の3本へ進む。
- 最後の1本でレビューの比較軸と従来の候補順位が分かれる場合、先に「実戦推奨」を示し、従来案は「基準例」として区別する。基準順位と RouteGrade の値は書き換えない。
- 合法な成立案は TRAINING で正解として受け入れ、SIMULATION では必要なら比較上の不利を理由付きで示す。狙い通り BUST する案とは分類を分ける。
- 学習履歴のカテゴリ名は表示だけ日本語化し、保存キー・履歴・集計と復習対象は維持する。


## 5. アーキテクチャ

```
UI (components / pages / hooks)
        ↓ 参照のみ
Engine (checkout / setup / recovery / ranking / training / simulation)
        ↓ 参照のみ
Data (基準ルート / Bogey / 隣接 / 重み / 説明文 / 資料フィクスチャ)
        ↓ 参照のみ
Domain (盤面 / 得点 / ダート / Double Out ルール)

Storage (localStorage) は UI からのみ使う
```

戦術データを React コンポーネントへ直書きしない。
評価理由は reason code として構造化し、表示用の日本語は `src/data/explanations.ts` で解決する。

SIMULATION のゲーム進行と着弾モデルは `engine/simulation/**` に閉じる。
最後の1本の実戦選択だけは、レビューと `suggestFor()` が共通の純粋関数を参照する。
既存の基準順位・戦術データは変更しない。
着弾シミュレーションだけは表示座標系ではなく**実寸（mm）のボード**を使う
（理由と写像は `docs/SIMULATION_DESIGN.md`）。

## 6. 性能

- チェックアウトの探索は (残り点, 本数) 単位でキャッシュ。全ルート列挙でも数ミリ秒。
- SETUP は取得点ごとの代表シーケンス表を 1 度だけ構築し、以降は取得点 0〜180 の走査だけ。
  アプリ起動後、`requestIdleCallback` で表を温めておく。
- 正しさを優先し、複雑な最適化は必要になってから入れる。

## 7. アクセシビリティ

- SVG の全区画に `aria-label`（例: 「トリプル20、60点」）
- キーボード操作（Tab で移動、Enter / Space で選択）
- タップ領域は 44px 以上（`min-height: 2.75rem`）
- `:focus-visible` のフォーカスリング
- `prefers-reduced-motion` に対応
