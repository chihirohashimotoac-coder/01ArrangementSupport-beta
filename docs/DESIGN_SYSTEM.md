# DESIGN_SYSTEM.md — 見た目の規則（Calibrated Instrument）

画面の配色・書体・余白・部品の規則です。実装の Source of Truth は
`src/index.css` の semantic token で、各コンポーネントはそれだけを参照します。
画面ごとの構成（何をどの順に置くか）は `docs/UI_SPEC.md` を参照してください。

## 1. コンセプト

**Calibrated Instrument** — 3 投を測る精密な計器。

- 本体は無彩色。Dark はグラファイト、Light はアルミ。
- 主操作は「反転」で示す。Dark ではチョーク色の面にインクの文字、Light ではその逆。
  装飾のための色（グラデーション・発光・ブランド色）は持たない。
- **色は意味にだけ使う。** 推奨度 S / A / B / C、判定（良い・見直し・誤り）、
  盤面の実物の配色、盤面で指している的（target）。
- **数字が主役。** 残り点・ターゲット・本数は、幅を詰めた等幅数字で大きく組む。
  入力欄や残り点の表示は「凹んだ窓」（`--surface-alt` + `--inset-well`）に置く。

## 2. 色

| token | Dark | Light | 用途 |
| --- | --- | --- | --- |
| `--background` | `#15181b` | `#e7e9ec` | 画面の地。`theme-color` と manifest も同じ値 |
| `--surface` | `#1c2024` | `#f6f7f8` | パネル |
| `--surface-alt` | `#111417` | `#e0e3e6` | 凹んだ窓（入力・数字の表示・セレクターの溝） |
| `--surface-elevated` | `#23282d` | `#ffffff` | 浮かせる面（答えのカード・得点入力） |
| `--text` | `#eeece7` | `#15181b` | 本文・数字 |
| `--text-secondary` | `#b5b9be` | `#444b53` | 補足 |
| `--text-dim` | `#8e949b` | `#5b626b` | 注記（本文サイズでも 4.5:1 以上） |
| `--accent` | `#eeece7` | `#15181b` | 主操作・選択中の面（反転） |
| `--grade-s/a/b/c-*` | 緑 / 青 / 黄 / 赤 | 同系の濃色 | 推奨度。判定の 良い / 見直し / 誤り にも同じ系統を使う |
| `--target` | `#e3a64a` | `#845000` | ルートのチップで盤面の位置を確かめている的（盤面の focus と同じ色） |
| `--danger-solid` | `#b3261e` | `#a3231c` | 取り消せない操作の確認ボタン（白文字） |
| `--scrim` | 黒 62% | インク 42% | モーダルの背面を沈める幕 |
| `--segment-*` / `--board-*` | 実物のダーツボード | 同左 | 盤面。テーマで大きく変えない |

- 推奨度・判定の色は**文字（S / A / B / C、判定名）と必ず併記**する。色だけで区別しない。
- 理由の極性（強み / 注意）も色に加えて `+` / `−` の記号を置く。
- コントラストは本文 4.5:1、大きな文字 3:1 以上（WCAG 2.x AA）を両テーマで満たす。

## 3. 書体

- **Archivo**（可変幅 62–125%・可変ウェイト、SIL OFL 1.1）。ラテン文字のサブセットだけを
  `src/assets/fonts/` に同梱し、Service Worker で precache する（オフラインでも同じ表示）。
  ライセンスは `src/assets/fonts/OFL-Archivo.txt`。
- 日本語は端末のシステムフォント（Hiragino Sans / Noto Sans JP / Yu Gothic UI / Meiryo）。
  日本語の Web フォントは容量が大きく、オフライン PWA の precache を膨らませるため同梱しない。
- 数字は `font-stretch: 74–78%` + `font-variant-numeric: tabular-nums`。
  残り点・ターゲット・統計・表など、桁がそろって欲しい所にだけ使う。
- 見出し・区画名は日本語の文として置く。英大文字の飾りラベル（`APPEARANCE` など）は置かない。
  `CHECKOUT` / `SETUP` / `STANDARD` / `BEST` / `MY ROUTE` / `NEXT VISIT` / `LEFT` / `DARTS` /
  `BUST` などは、競技とこのアプリの用語なのでそのまま使う。

| token | 値 | 主な用途 |
| --- | --- | --- |
| `--text-2xs` | 0.6875rem | 札（バッジ）・単位 |
| `--text-xs` / `--text-sm` | 0.75 / 0.8125rem | 注記・補足 |
| `--text-md` / `--text-base` | 0.9375 / 1rem | 本文 |
| `--text-lg` / `--text-xl` | 1.1875 / 1.5rem | 小さなターゲット表示・小見出し |
| `--text-2xl` / `--text-3xl` | 2 / 2.75rem | 計器の読み取り値 |

## 4. 余白・形

- 余白は 4px 基準（`--space-1` 0.25rem 〜 `--space-8` 3rem）。
- 角丸は階層で変える。札 3px（`--radius-xs`）/ ボタン・入力 6px（`--radius-s`）/
  パネル 10px（`--radius-m`）。ピル型のボタンは使わない。
- タップ領域は 44×44 CSS px 以上（`--tap`）。
- 内容の最大幅は 76rem。文章は 44rem 前後に収める。

## 5. 部品

| 部品 | 規則 |
| --- | --- |
| セレクタースイッチ | ナビ・残り本数・TRAINING のモード・SIMULATION の選択肢。凹んだ溝の中で、選んだものだけが反転して浮く |
| 主ボタン | `--accent` の面 + `--accent-contrast` の文字。1 画面に 1 つを原則にする |
| 副ボタン | 透明 + `--border-strong` の枠 |
| 表示窓 | `--surface-alt` + `--inset-well`。残り点の入力・StatusBar・3 投の並び・回答枠 |
| 答えのカード | `--surface-elevated` + `--shadow-md`。札（STANDARD / BEST）を反転させる |
| 候補の一覧 | カードを積まず、1 枚のパネルを罫線で区切る。推奨度の札は行の右端でそろえる |
| 開閉 | 文言（理由を見る / 閉じる）+ 回転する山形。`aria-expanded` と連動 |
| 注意 | 左の色帯 + 淡い地。危険（Bust・ノーテン）は赤系、判定は推奨度と同じ系統 |

### 5-1. 操作部品（`src/components/ui/`）

表示と操作だけを受け持つ部品。engine・保存・採点の結果を変えない（値は呼び出し側が渡す）。

| 部品 | 使う場所 | 規則 |
| --- | --- | --- |
| ハンバーガーメニュー（`AppMenu` + `Modal` drawer） | ヘッダー右端 | ホーム・4 モード・設定・バージョン履歴・参考資料・テーマを 1 枚に集める。右から出るドロワー。3 本線は開くと × に組み変わる |
| パンくずリスト（`Breadcrumbs`） | ホーム以外の全画面（ヘッダー直下） | `ホーム › 画面 › 状況`。最後は `aria-current="page"` で押せない。CHECKOUT / SETUP の「残り 103」から画面名を押すと入力前へ戻る |
| カルーセル（`Carousel`） | ホームの「例題で見る」 | scroll-snap でスワイプ。前後ボタン・ドット・矢印キー。自動送りはホバー・フォーカス中と停止ボタンで止め、動きを減らす設定では最初から止める。見えないスライドは `inert` |
| モーダル（`Modal` / `ConfirmDialog`） | メニュー、学習履歴の消去、SIMULATION の中断 | `role="dialog"` + `aria-modal`。Tab を閉じ込め、Esc と背景で閉じ、開く前の要素へフォーカスを戻す。取り消せない操作の確認は既定フォーカスを「キャンセル」側に置き、実行ボタンは `--danger-solid` |
| アコーディオン（`Accordion`） | ホームのヒント、学習履歴の内訳表、バージョン履歴 | 見出しの中のボタン + `aria-expanded` / `aria-controls`。閉じた領域は `inert`（DOM には残す）。高さは `grid-template-rows: 0fr → 1fr` で伸縮 |
| ラジオボタン（`RadioGroup`） | TRAINING の出題数・制限時間、メニューのテーマ | ネイティブの `<input type="radio">`。`segmented` は溝の中を反転した面が滑る、`cards` は丸い印が内側から満ちる |
| プルダウン（`Select`） | TRAINING の出題範囲プリセット、バージョン履歴の「版を選んで開く」 | ネイティブの `<select>`（スマートフォンでは OS 標準の選択 UI）。凹んだ窓 + 山形 |

### 5-2. インフォグラフィック（`Infographic.tsx`）

図は `aria-hidden`。同じ数値を必ず文字でも置き、色だけ・長さだけで伝えない。

| 図 | 使う場所 | 内容 |
| --- | --- | --- |
| 円環ゲージ（`RingGauge`） | 学習履歴 | 正答率。10% ごとの目盛りの上を輪が描かれていく |
| 横棒（`Meter`） | 学習履歴の内訳表 | 正答率の列に同じ値の棒。アコーディオンを開くたびに伸び直す |
| 積み上げ帯（`StackedBar`） | 学習履歴（推奨度）、SIMULATION（判断の内訳） | 推奨度・判定の色 token で塗り分け、左から順に伸びる |
| 残り点の地図（`ScoreMap`） | ホーム | 0〜350 の数直線に CHECKOUT / SETUP / TRAINING の範囲の帯を重ねる。境界は `MAX_CHECKOUT` などの定数から作る |

## 6. 動き

「操作に応える」「状態の変化を知らせる」「数字を主役にする」ための動きを、量を絞らずに使う。
ただし**答えの読み取りを邪魔しない**ことを最優先にする。

| 種類 | 例 | 規則 |
| --- | --- | --- |
| キネティックタイポグラフィ | ホームの題字（1 字ずつせり上がり、「判断の規則」だけ反転した札に変わる）、背景の数字札 501 → 0、SIMULATION の `GAME SHOT`、BUST / CHECKOUT! のスタンプ、残り点のオドメーター（`RollingNumber`） | 読み上げには分割前の文を渡し、分割した文字は `aria-hidden`。オドメーターは DOM の文字を常に最終値に保つ（途中の数字を出さない） |
| UI / UX アニメーション | 画面の入場（`view-in`）、モード切り替えの反転面が滑る、メニューの項目が順に滑り込む、ルートの数字札が弾む、推奨度のスタンプ、候補一覧の流し込み、アコーディオンの伸縮、盤面で指した的の脈動 | 1 回きりを原則にする。繰り返すのは「指した的」の脈動と、自動送り中のカルーセルの進み具合だけ |
| インフォグラフィックアニメーション | 円環ゲージ、横棒、積み上げ帯、残り点の地図 | 画面に入ったとき（`useInView`）に一度だけ伸びる |

- **答えのカードの位置は動かさない。** STANDARD / BEST は clip-path で上から幕が開くように現れ、
  `transform` は使わない。答えへのスクロール位置（入力完了時の移動）を乱さないため。
  clip-path は影も切るので、終わったあとに残さない（`animation-fill-mode: backwards`）。
- イージングは `--ease-out-expo`（伸びる・現れる）と `--ease-spring`（つまみ・山形・スタンプ）。
- ホバーでは要素を持ち上げない。下線・矢印・面が「伸びる」動きにとどめる。
- 押したときは `scale(0.985)`。
- `prefers-reduced-motion: reduce` ではすべて止め、**待ち時間（delay）も 0 にする**（`src/index.css`）。
  モーダルは退場を待たずに外し、カルーセルは自動送りしない。動きが無くても、状態は文字と色で伝わる。

## 7. レイアウト

| 幅 | 構成 |
| --- | --- |
| 〜47.9rem | 1 列。ヘッダーは「アプリ名・メニュー（☰）」+ 2 段目にモードの切り替え、その下にパンくず |
| 48rem〜 | 入力・設定パネルを横長にまとめる。ホームは 2×2 |
| 64rem〜 | ヘッダーを 1 行に（アプリ名・モード・メニュー）。ホームの例題と地図は 2 列。CHECKOUT / SETUP は「答え・実戦入力」｜「他の候補」の 2 列、TRAINING / SIMULATION は「盤面」｜「状況・入力・結果」の 2 列。ホームは 4 列 |

2 列にするときも DOM の順序は変えない（読み上げ順とスクロールの挙動はスマートフォンと同じ）。
