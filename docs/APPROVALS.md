# APPROVALS.md — 戦術方針の人間承認記録

このリポジトリの戦術データ（基準ルート・評価の重み・教材ルール）は、
**計算で一意に決まるものではなく、人間が選んだ方針**です。
このファイルは「誰が・いつ・何を承認したか」を残すための記録です。

---

## 用語について（重要）

このファイルに並ぶ値を、**「数学的・統計的に絶対正しい値」とは呼びません。**

- 算術・ルール上の正しさ（合計が LEFT と一致する、最終ダートがダブルである、
  Bogey かどうか、など）は engine が計算し、テストで検証しています。
  これは**検証可能な事実**です。
- 一方、「どちらのルートを推奨するか」「どの残しをより良いとするか」は
  **戦術的な価値判断**であり、計算だけでは決まりません。
  ここに記録するのはそちらです。

したがって本ドキュメントおよび関連ドキュメントでは、次の表現を使います。

| 使う表現 | 使わない表現 |
| --- | --- |
| 人間承認済みの v1 戦術方針 | 数学的に正しい値 |
| v1 暫定値 | 統計的に最適な重み |
| v1 で採用した思想 | 唯一の正解 |

v1 は**運用しながら見直す前提の暫定値**です。
変更するときは、このファイルへ v2 として追記し、あらためて人間の承認を得てください。

## 承認 v1.3.4

**承認日**: 2026-09-14
**承認者**: リポジトリオーナー（chihiro.hashimoto.ac@gmail.com）
**対象**: 「NEXT VISIT / SETUP SAFETY / TRAINING REDESIGN」の指示
**位置づけ**: v1 の思想を保ったまま、**新しい戦術判定軸を追加**する変更として承認。

ユーザー指示の本文が、そのまま次の 5 点の承認にあたる。

### A-9. NEXT VISIT は、同等条件なら自然な mainTarget 始動を優先する

NEXT VISIT の比較順を

1. NEXT VISIT Tier（残しが次ラウンド何本で上がれるか）
2. いま投げるルートの難易度
3. **主目標（既定 T20）から始められるか**
4. 得意ダブル
5. 残しの質
6. 的の切替 / 順番の good practice
7. 最終 tie-break（キー）

とする。3 を足した理由は、同じ取得点・同じ残し・同じ難易度のとき、
最後に**表記の辞書順**が戦術判断を決めていたため（125 / 2 本の `T11 → T20`）。

あわせて、候補生成で主目標始動が枝刈りされないよう、
`mainTargetFirstSequenceTable()` を追加する（重みではなく候補の話）。

残り 1 本は「順番」の問題ではないので、この軸は効かせない。

### A-10. 残しの質に「半分にし続けられる回数」を使う

NEXT VISIT の残し比較に `halvingDepth`（32 → 16 → 8 → 4 → 2 なら 5）を使う。

新しい戦術思想ではなく、すでに承認済みの

- `src/data/lowStandardRoutes.ts` の R2（奇数は 32 → 16 → 8 → 4 → 2 の順に
  立て直しやすいダブルを作る / A-4）
- `DOUBLE_QUALITY` が D16 を excellent とする理由（「half が続き、外しても
  立て直しやすい」）

と同じ考え方を、NEXT VISIT でも使えるよう数値にしたもの。
新しい重み定数は作っていない（順序としてだけ使う）。

### A-11. SETUP は第一トリプルの「同ナンバーシングル落ち」耐性を評価する

`isSingleMissTenpaiSafe(remaining, firstDart, dartsAvailable)` を追加し、
`rankSetupRoutes()` のふるいを

1. テンパイを残せて、かつ第一ターゲットがシングルへ落ちても立て直せる
2. テンパイを残せる（1 が空の場合）
3. 条件なし（テンパイを作れない残り点）

の 3 段にする。**重みでは順位を作らない**。既存の `tenpaiOnly` と同じ
「条件を満たすものだけを見る」構造にそろえてある。

- 残り 1 本では 1 が必ず空になるため、302〜309 のラスト 1 投調整は変わらない。
- BULL エリアは「同ナンバーのシングル」というモデルが当てはまらないため対象外。
  安全と決めつけない側へ倒す（`SETUP_THEORY.md` §8 の方針とも向きが揃う）。
- 表示用の理由コード `SETUP_SINGLE_MISS_TENPAI_SAFE` /
  `SETUP_SINGLE_MISS_DEAD_END` を追加する。**重みは 0**（順位はふるいで決まる）。

結果として 171〜350 × 1〜3 本のうち BEST が変わるのは 11 件で、
すべて「取得点と残しは同じまま、危険な T20 を後ろへ回す」並べ替えになる。

> **v1.3.7 で見直し**: この実装は「S19 を狙う」という結果を生んでいた。
> 意味論の修正は **A-18** を参照（A-11 の判定そのもの・重みは変更していない）。

### A-12. SETUP TRAINING の 3 投自由形式を、第一ターゲット判断へ置き換える

- `setup-full` の**新規出題を停止**する（型・採点・保存済み履歴の読み込みは残す）。
- `setup-first-dart`（3 投あるラウンドの 1 投目だけを答える）を追加する。
  - 出題は「第一ターゲットによってシングル落ち耐性に差が出る残り」だけ。
  - **採点**は盤面のすべてのトリプルを規則どおり判定する（ランキングの上位何件に
    現れるかで正解・不正解が変わってはいけない）。
    広いシングルを狙うのを「安全だから正解」にはしない。
  - **出題する残り点**は、取得点の多い上位 3 つ（ふつう T20 / T19 / T18）で
    安全性が分かれるものだけ。誰も狙わない的が危険というだけの残りは出さない。
  - 唯一の正解を固定せず、安全な代替も正解として推奨度（S/A/B/C）で差を付ける。
- 出題比率は 80% `setup-adjustment` / 20% `setup-first-dart`。
- 教育カテゴリへ `setup-first-dart-safety` を 1 つだけ追加する。

### A-13. ラスト 1 投問題は「調整判断が必要なケース」を優先する

`decisionRequired` を追加し、1 投調整の出題を「自然な狙い（直前と同じナンバー /
主目標の 20）のどこへ入っても上がれる、とは言えない場面」に絞る。

固定の下限（182 以上など）ではなく計算で決めるので、179（S20 で 159）も入り、

`setup-basics` / `setup-bogey-avoid` / `setup-adjust-18-19-20` の 3 カテゴリは

それらの学習内容は `setup-same-number-worse` などの具体的なカテゴリと、
`shift-20-to-18` / `shift-20-to-19` の学習タグが引き続き担う。

ユーザーが出題範囲を狭くして該当が 1 件も無くなる場合（例: 171〜182）は、

### A-14. 得意ダブルが残しの質より優先されるのは「第 1 希望だけ」

NEXT VISIT の比較で、得意ダブルの順位付きリスト全体を残しの質より上に置かない。
**第 1 希望に選ばれたダブルちょうどで上がれる残し**だけが残しの質より優先され、
第 2 希望以下は、残しの質が完全に並んだときの同点処理にだけ使う。

理由は、アプリが既定で D16 → D20 → D8 → D10 → D18 の 5 件を選択済みにしていたため。
ユーザーが何も設定していなくても「第 2 希望の D20（40 残し）が
第 3 希望の D8（16 残し）に勝つ」という戦術判断が既定値から生まれていた。

あわせて、**得意ダブルの既定を「未設定（空）」にする**。
得意ダブルは本人が選んだときだけ効く設定とし、アプリ側で順位を持たない。
設定画面では複数選べること・並び順が優先度であること・第 1 希望だけが
NEXT VISIT にも効くことを明記する。
未設定のあいだ、CHECKOUT の MY ROUTE カードは表示しない（従来どおりの挙動）。

影響は 28 状態（61 / 63 / 64 / 66 / 67 / 69 / 70 / 72 / 73 / 75 / 76 / 78 / 81 / 84 の
1 本、121 / 123 / 124 / 126 / 127 / 129 / 130 / 132 / 133 / 135 / 136 / 138 / 141 / 144 の 2 本）。
すべて「40 → 16」「36 → 24」と、半分が続く深い残しへ変わる。
第 1 希望を D20 にしているユーザーの結果は変わらない（103 / 2 本は T20 → S3 のまま）。

`SEGMENT_DIFFICULTY` / `DOUBLE_QUALITY` / SETUP の重みは変更しない。

### A-15. ラスト 1 投の出題は「狙うナンバーを変えると結果が変わる」ときだけ

`decisionRequired` の判定を、次の 2 つが同時に成り立つときに変更する。

1. シングル面に入ってもトリプル面に入っても上がれるナンバーが存在する
2. しかし自然に狙うナンバー（直前と同じナンバー / 主目標の 20）はどれもそうではない

固定の下限ではなく計算で決めるため、結果として出題されるのは
**179 / 182 / 183 / 185 / 186 / 188 / 189**（Bogey Number + 20）の 7 つだけになる。
192 のように「T20 なら 132 で普通にテンパイ、ほかを狙っても同じ」場面と、
194 のように「どのシングル面でも 170 を超える」場面は出題しない。

BULL エリアはナンバーの候補に含めない。「狙って外すと同じナンバーのシングル面」
というモデルが当てはまらないため（A-11 で `singleMissDartOf()` が BULL を
対象外にしているのと同じ理由）。

### A-16. SETUP の回答は「どのナンバーを狙うか」

SETUP TRAINING（1 投調整・1 投目の選択）の回答は、盤面 62 セグメントではなく
1〜20 のナンバーから選ぶ。採点もナンバー単位で行う。

入力方法は、**盤面で 1 ナンバーぶんのウェッジ（シングル・トリプル・ダブルを
まとめた扇形）をタップする**方式にする。数字のボタンを並べると、盤面の並び
（20 → 1 → 18 → …）と一致せず、目的のナンバーを探す時間がかかるため。
BULL は選べない（中心は 20 個のウェッジが 1 点に集まり、狙いが決まらない）。
CHECKOUT / RECOVERY の実戦入力は、これまでどおり 62 区画から選ぶ。

- 1 投調整 … シングル面・トリプル面の**両方**で上がれる残りになれば正解
- 1 投目の選択 … 従来どおり（狙ったトリプルと、同ナンバーのシングル落ち）

「T20 に入れば 122 で上がれる」だけでは正解にしない。ラスト 1 投の調整は
外れ方まで含めてナンバーを選ぶ判断であり、それがこの教材の主題だから。

安全なナンバーが 1 つも無い残り（190 以上など）では、存在しない安全さを要求せず、
これまでどおり「実際に作った残りが上がれるか」で採点する。

### A-17. NEXT VISIT は最大 3 件まで提案する（v1.3.6）

出典: ユーザー指示（2026-09-15）。

> 残りの投数で上がれない数字の場合、提案されたアレンジを投げると残り何点に
> なるかの表示もしてください。また、提案するアレンジは得意ダブルを考慮しない
> 場合と得意ダブルを考慮した場合の複数種類を提案してください。多くても最大 3 つに
> してください。得意ダブルと被る場合や 1 種類しかない場合は 1 つのみの表示にし、
> 同じアレンジが重複して表示されないようにしてください。

実戦入力で上がれない場面では、次の順で最大 3 件を出す。

1. 既定の案内（A-14 の比較順そのまま）
2. 得意ダブルの**順位**を残しの質より上に置いた場合の案
3. 的を切り替えずに作れる案（第 1 候補と同じ Tier で、難易度を上げないもの）

同じルートは重複させない。2 が 1 と同じ、または得意ダブル未設定なら 2 は出さない。
3 は条件に合うものが無ければ出さない（無理に 3 件並べない）。
各件に「投げたあとの残り点」を必ず添える。

第 1 候補の選び方（A-14）は変えない。2 は「設定を反映するとどうなるか」を
見せるための並べ方であって、既定の案内を得意ダブル順へ戻すものではない。

### A-18. SETUP の第一ターゲットは「狙う得点用トリプル」に限る（v1.3.7）

A-11 のシングル落ち耐性は、**「得点のために得点用トリプルを狙い、同ナンバーの
シングルへ落ちた」**場合の評価である。ところが `singleMissDartOf()` は
S19 を渡すと S19 を返すため、シングルを狙うルートが「外しても着弾が変わらない」
という理由だけで耐性ありと判定され、通常 SETUP の第一ターゲットに
`S19` / `S18` が選ばれていた。

第一ターゲットの選択でも同じ意味論を使う。

1. `rankSetupRoutes()` のふるいの最上段に
   **「テンパイを残せて、得点用トリプル（T1〜T20）から始まり、そのトリプルが
   シングルへ落ちても立て直せる」** を足す（4 段構成）。
   安全な得点用トリプルが 1 つも無ければ空になり、A-11 のふるいへ落ちる。
2. **主目標（既定 T20）が安全なら、シングル落ち耐性を理由とした振り直しはしない。**
   候補は安全な得点用トリプル全体で、そのどれを狙うかは
   **従来どおりビジット全体の評価**（残りの質 → 取得点 → 難易度）が決める。

   これは「主目標が安全なら必ず主目標から投げる」という意味ではない。
   残りの質の方が取得点より重い（A-7）ため、T20 が安全でも別のトリプルの方が
   良い残しを作れる残り点では、そちらが第 1 候補になる。これは v1.3.4 以前からの
   挙動で、本項で変えていない。

   例: 279 / 3 本（T20 は安全）
   | | ルート | 残し | 評価 |

### A-26. ビジット最後の 1 投で、命中時のダブルとシングル落ちの交換条件を上位互換と断定しない

A-22 はビジット最後の 1 投で、狙い通り・シングル落ちの両方で悪化せずどちらかで改善する的を
明確な上位互換とする。外側のダブルはすべて同じ段階なので、狙い通りのときに**どのダブルが残るか**が
比較に入らず、アプリの NEXT VISIT 第 1 案（77 の T15 → D16、79 の T13 → D20、80 の T16 → D16）が、
シングル落ち後に有利な代案（T19 → D10、T19 → D11、T20 → D10）を理由に `BETTER` になっていた。

承認された範囲は次のとおり（オーナーの指示の要旨）。

> 適用範囲は、ビジット最後の 1 投で、アプリが実際に表示した NEXT VISIT 提案の初投に限定する。
> 狙いとレビュー側の代案が、命中時にともに外側ダブルを直接残し、得意ダブル設定が代案側を優先
> していない場合は、シングル落ち後の差だけを理由に「明確な上位互換」と断定せず GOOD にする。
> 得意ダブルに両方が含まれる場合の優先順位も明示的に扱う。

- 交換条件（すべて満たすとき）: ①狙いが表示された NEXT VISIT の提案の 1 投目 ②狙い・代案とも
  狙い通りなら外側ダブルを直接残す ③その 2 つのダブルが違う ④得意ダブルの設定が代案側を優先しない
  （代案のダブルだけが含まれる → 代案優先。両方含まれる → 順位が上の方が優先）。
- A-22 の上位互換の的がすべて交換条件なら `GOOD DECISION`（理由コード `LAST_DART_DOUBLE_TRADE_OFF`）。
  1 つでも交換条件でない上位互換の的があれば従来どおり `BETTER OPTION AVAILABLE`。
- 説明文に、狙い通り・シングル落ちの交換条件を具体的な残りで書く。日本語は `src/data/explanations.ts`。
- ダブルの扱いやすさ（`DOUBLE_QUALITY`、v1 承認の対象外）は判定に使わない。

**影響（全 64,914 状態）**: 得意ダブル未設定・D20・D16・D8 で 3 件（77 の T15・79 の T13・80 の T16）、
D10 で 1 件、D11 で 2 件、D16 / D20 / D8 で 5 件（73 の T11・76 の T12 を含む）。すべて `BETTER` → `GOOD`。
116 の S16・99〜120 の 20 件・A-21 の 20 件・178・243 は変わらない。監査項目 G は修正前 20 件 → 修正後 0 件。
